# 段階別開発規格書 (SPEC.md) - 配色小助手 (Color Palette Assistant) MVP

本規格書は、Google Antigravity IDEのAgentが自律的に開発・検証を進めるための段階別仕様書です。  
開発は必ず指定された段階（Phase）ごとに行い、各段階の終了時に「AI自動検証」と「開発者手動確認」を実施してください。**開発者の手動確認による承認を得る前に、次の段階の実装へ進むことは厳格に禁止します。**

---

## 📌 プロジェクト概要・基本原則
- **アプリ名**: 配色小助手 (Color Palette Assistant)
- **目的**: デジタルコンテンツ制作時の色選びの迷いを解消し、迅速に調和の取れた5色パレットを決定・確認・コピーできるWebアプリ。
- **技術スタック**: Pure HTML5 / CSS3 / JavaScript (ES6) のみ（フレームワーク・外部ライブラリ・外部API・バックエンドサーバー・データベースは一切使用しない）。
- **非機能要件・除外スコープ**: ユーザー登録/ログイン、クラウド保存、DB、AI画像認識、外部連携(Figma等)、SNS共有、チーム共有、高度な色彩分析(PCCS等)は実装対象外。

## 🛠️ フェーズ1：基本画面構成と基準色選択機能（MVPプロトタイプ）

### 1. 【開発タスク】
- **UIレイアウトの構築**:
  - タイトルヘッダー（「配色小助手」のタイトルと使い方ガイド）
  - 1カラムの縦長レスポンシブレイアウト（CSS Flexbox/Gridを使用、外部CSSフレームワーク不使用）
- **基準色選択エリアの実装**:
  - HTML標準カラーピッカー (`<input type="color" id="baseColorPicker">`)
  - よく使われるプリセットカラー（ブルー `#3B82F6`、レッド `#EF4444`、グリーン `#10B981`、イエロー `#F59E0B`、パープル `#8B5CF6`）のクイック選択ボタン
- **選択色のリアルタイム表示**:
  - 選択中の基準色を大きく見せるカラーチップ（色見本ボックス）
  - 選択中の色のHEXコード（例: `#FF5733`）およびRGB値（例: `rgb(255, 87, 51)`）のテキスト表示

### 2. 【AI自動検証基準】 (Agentセルフチェック項目)
- [ ] ブラウザのConsoleにJavaScriptのエラーや警告が発生していないこと。
- [ ] カラーピッカー（`<input type="color">`）が要素として正しく描画され、操作可能であること。
- [ ] カラーピッカーで色を変更した際、カラーチップの背景色およびHEX/RGBテキスト表示がリアルタイムに更新されること。
- [ ] 5つのプリセットカラーボタンをクリックした際、指定したHEXカラーがカラーピッカーおよび画面表示に即座に反映されること。

### 3. 【開発者手動確認基準】 (開発者チェックリスト)
- [ ] 画面上にアプリタイトル「配色小助手」と直感的なレイアウトが表示されているか？
- [ ] カラーピッカーから好きな色を選択すると、選択した色がカラーチップとテキスト（HEX/RGB）に即座に反映されるか？
- [ ] プリセットカラーボタン（青・赤・緑・黄・紫等）を押すと、その色に一瞬で切り替わるか？
- [ ] レスポンシブまたは崩れのない整った見た目になっているか？

## 🎨 フェーズ2：配色パレット自動生成・コピー・デザインプレビュー機能（核心機能）

### 1. 【開発タスク】
- **5色パレット自動生成ロジック**:
  - 基準色のHEX値をRGB/HSL色空間に変換し、以下の5色のパレットを自動計算・生成するJavaScript処理の実装。
    1. **基準色**: ユーザー選択色
    2. **類似色**: Hue +30°
    3. **補色**: Hue +180°
    4. **明るい色**: Lightness 85%（背景・ハイライト用）
    5. **暗い色**: Lightness 20%（テキスト・枠線用）
- **パレット表示＆HEXコピー機能**:
  - 5色のカラーチップ、役割名（「基準色」「類似色」等）、HEXコードを並べて表示。
  - カラーチップまたは「コピー」ボタン押下時に、該当のHEXコードをクリップボードにコピー (`navigator.clipboard.writeText`)。
  - コピー成功時に画面上に「HEXコードをコピーしました」というトースト通知を表示。
- **デザインプレビューエリアの実装**:
  - ミニチュアWebサイト/ポスター風のUIカードを配置。
  - 生成された5色がリアルタイムでプレビューUI要素に自動適用される。
    - ヘッダー・主要ボタン ➔ 基準色 / 補色
    - カード・背景領域 ➔ 明るい色
    - テキスト・枠線 ➔ 暗い色

### 2. 【AI自動検証基準】 (Agentセルフチェック項目)
- [ ] ConsoleにJavaScriptエラーが発生していないこと。
- [ ] 基準色を変更した際、5色（基準色・類似色・補色・明るい色・暗い色）のパレットとHEX表示が正しく更新されること。
- [ ] コピーボタン押下時に `navigator.clipboard` が実行され、コピー完了のトースト通知がUI上に一時表示されること。
- [ ] デザインプレビュー領域内の各種要素（ボタン、背景、テキスト）に、計算された5色が正しく適用されていること。
- [ ] **（回帰テスト）** フェーズ1で実装したプリセットボタンおよびカラーピッカーが正常に連動し続けていること。

### 3. 【開発者手動確認基準】 (開発者チェックリスト)
- [ ] 基準色を変えると、類似色・補色・明るい色・暗い色の5色パレットが即座に自動生成・更新されるか？
- [ ] 表示されているHEXコードのコピーボタンを押すと、クリップボードに正しいHEXコードがコピーされ、トースト通知が出るか？
- [ ] 下部のデザインプレビュー画面で、生成した配色がWebサイト風UI（ボタンや背景、文字）に適用されて実際のイメージが確認できるか？
- [ ] 前段階の機能（カラーピッカーやプリセット選択）は問題なく動作しているか？

## 💾 フェーズ3：データ保持・UI調整・エラーハンドリング・最終MVP完成

### 1. 【開発タスク】
- **ローカル状態の保持（LocalStorage）**:
  - ブラウザの `localStorage` を使用し、最後に選択した基準色を保存・自動読み込みする処理の実装。
  - ページをリロード（再読み込み）しても、直前に選んでいた色が保持され、5色パレットとプレビューが復元される仕組み。
- **コピー機能のフォールバック・エラーハンドリング**:
  - クリップボードAPIが制限されている環境（`file://` や一部ブラウザ設定）でもエラーで停止しないよう、フォールバック処理（またはエラー回避トースト表示）を実装。
- **UI/UXの微調整と仕上げ**:
  - マウスオーバー時のインタラクション（ボタンのホバー効果、カラーチップの拡大アニメーション等）。
  - 各エリアの余白、フォント、可読性の整え（全画面・モバイル表示の崩れ防止）。

### 2. 【AI自動検証基準】 (Agentセルフチェック項目)
- [ ] Consoleに未捕獲の例外エラー（Uncaught Error）が一切存在しないこと。
- [ ] 基準色を変更後、ページをリロード（`location.reload()`）した際に、`localStorage` から保存された色が読み込まれ、変更後の状態で画面が描画されること。
- [ ] クリップボード操作で例外が発生した場合も、エラー処理によってアプリケーション全体がクラッシュしないこと。
- [ ] **（回帰テスト）** フェーズ1・フェーズ2の全機能（カラーピッカー、プリセット、5色計算、コピー、プレビュー）が破綻なく正常動作すること。

### 3. 【開発者手動確認基準】 (開発者チェックリスト)
- [ ] 好きな色を選んだ後、ブラウザのページを再読み込み（F5 / Ctrl+R）しても、最後に選んだ色が保持されているか？
- [ ] ボタンやカラーチップにマウスを乗せた際, 分かりやすいインタラクション（ホバー効果）があるか？
- [ ] エラーや画面の崩れがなく、直感的でスムーズに操作できる「配色小助手」のMVPとして完成しているか？
